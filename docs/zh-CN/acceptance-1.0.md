# Career Steward 1.0 中文验收说明

[简体中文](acceptance-1.0.md) | [English](../acceptance-1.0.md)

自动化验收证明本地模块化单体能够完成一个完整求职流程，同时不绕过持久化、版本和确认边界。

## 自动化验收旅程

执行：

```bash
npm run test:acceptance
```

测试使用一份自动生成、内容完全虚构的软件架构师文字型 PDF，并按顺序执行真实应用服务和 Store 事务：

1. 解析 PDF 证据，并确认 Candidate Profile revision 1；
2. 采集 JD，并确认岗位要求分析；
3. 生成并保存 Match Report，其中包含两个强项和一个 Kubernetes 明确缺口；
4. 确认分来源的公司调研和职业偏好；
5. 计算 Employer Fit，并验证未知 Deal Breaker 的分数上限；
6. 确认定制 CV，验证没有把未支持的 Kubernetes 要求写成候选人能力，并导出真实 DOCX；
7. 生成面试计划，明确为 Kubernetes 缺口安排准备；
8. 从收藏、开始准备、已投递到安排面试，追加用户确认的进展事件；
9. 构建动态工作台，验证当前产物完整时不会产生重复建议。

测试只写入临时工作区，不使用真实个人信息、实时模型或外部网站。语义提案使用确定性 fixture，因为验收目标是验证 Career Steward 的校验、版本、持久化和编排契约，而不是衡量某个模型的输出质量。

全量测试还会执行备份恢复往返：先创建快照，再写入后续数据，然后恢复快照，验证状态确实回到备份时点，并确认被替换的数据已经保存到 `pre-restore` 安全备份中。

## 人工质量检查

发布或演示前，建议完成以下环境相关检查：

- 在干净 Pi 工作区中执行本地安装并运行 `/career`；
- 导入一份经过授权和脱敏的真实文字型 PDF，检查证据位置；
- 在正常联网环境中，通过 `fetch_company_source` 获取官方、专业媒体、社区和奖项来源；
- 在 Microsoft Word 或 LibreOffice 中打开导出的 DOCX，检查分页、列表和字体；
- 交互完成一次确认流程和一次取消流程。

实时网站不会进入默认自动化测试，因为 DNS、robots 策略、登录、网页变化和服务可用性会导致发布信号不稳定。
